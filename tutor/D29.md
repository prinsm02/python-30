# Day 29: Fix bugs like a pro

Tutor notes for a helper model. Explain simply, give a hint before the answer, no em dashes.

**Idea of the day:** Find what is wrong calmly, and pick your capstone.

## Key points
- Three kinds of bug: will not start, crashes, or runs and gives the wrong answer.
- Read a traceback from the bottom: what went wrong, then which line.
- Print debugging: print the value just before the suspect line and compare with what you expected.
- Change one thing at a time, and run again after each change.

## Task 1: The crew counter
This should count the people in `crew.txt` but always says 1. It runs with no error: a logic bug. Fix it so it shows the right count, like `Crew: 4`. (Do not use `len`.)

Hints, in order:
1. Add a print(count) inside the loop. What happens to the number each time round?
2. count = 1 sets it to 1 every time. It never grows. What do you do to ADD one?
3. Change count = 1 to count += 1.

Answer:
```python
with open("crew.txt") as f:
    crew = f.read().split()

count = 0
for name in crew:
    count += 1
print("Crew:", count)
```

## Task 2: The overtime bug
A day rate is R100 per hour. The first 10 hours are normal. Each hour AFTER 10 is paid at 1.5 times. This program pays 1.5 times for ALL hours when you work more than 10. Fix it. For 12 hours the answer is `Pay: R1300.00`.

Hints, in order:
1. Work 12 hours by hand: 10 hours at R100, then 2 hours at R150. Does the program give that?
2. Only the hours over 10 get the 1.5. That is (hours - 10). The first 10 hours are 10 * rate.
3. pay = 10 * rate + (hours - 10) * rate * 1.5

Answer:
```python
rate = 100
hours = int(input("Hours? "))
if hours > 10:
    pay = 10 * rate + (hours - 10) * rate * 1.5
else:
    pay = hours * rate
print(f"Pay: R{pay:.2f}")
```

## Task 3: The runner's average
These are four runs in km. The average should be `10.95` and the longest `21.1`. This program has TWO bugs in the average, and runs without errors. Find both. You should see:

`Average: 10.95 km`
`Longest: 21.1`

Hints, in order:
1. Print total just after the loop. It should be 43.8. Is it?
2. Bug 1: range(1, ...) starts at index 1 and skips the first run. Lists start at 0. Bug 2: // throws away the decimals.
3. Change range(1, len(runs)) to range(0, len(runs)), and change // to /.

Answer:
```python
runs = [5.2, 10.0, 7.5, 21.1]
total = 0
for i in range(0, len(runs)):
    total += runs[i]
avg = total / len(runs)
print(f"Average: {avg:.2f} km")
print("Longest:", max(runs))
```

## On the PC: Use the real debugger and plan the capstone
Print debugging is quick. The VS Code debugger lets you freeze your program and look inside it. Then you choose the tool you will build next.

1. Open VS Code, open Python 30 Work (File, Open Recent), and open a terminal (Terminal, New Terminal). Check the line starts with `(.venv)`. If not, type `.venv\Scripts\Activate.ps1`.
2. Click the New File icon, name it `bugs.py`, and type:

prices = [100, 250, "75", 300]
total = 0
for p in prices:
    total = total + p
print("Total:", total)

Press Ctrl+S.
3. In the terminal type `python bugs.py` and press Enter. It crashes. Read it from the BOTTOM: `TypeError: unsupported operand type(s) for +: 'int' and 'str'`. The line above that points at line 4. The problem: "75" is text, not a number.
4. Fix it: change line 4 to `total = total + int(p)`. Save and run again. You should see `Total: 725`.
5. Now the debugger. Click in the grey strip just left of the number 4. A red dot appears: that is a breakpoint. Press F5. If a menu appears, choose Python Debugger, then Python File. If VS Code offers to install the Python Debugger extension, click Install.
6. The program freezes on line 4, which turns yellow. On the left, open Variables and look at `p` and `total`. Press F10 once to step one line and watch `total` change. Press F10 a few more times.
7. Press Shift+F5 to stop. Click the red dot again to remove it.
8. Plan your capstone: click New File, name it `PLAN.md`, and write three lines: the tool you will build after the course (the day-rate invoice tool, a call time sheet maker, or a run log summary), one sentence on who will use it, and the first small step. Save with Ctrl+S.
