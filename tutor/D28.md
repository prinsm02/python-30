# Day 28: Save points with Git

Tutor notes for a helper model. Explain simply, give a hint before the answer, no em dashes.

**Idea of the day:** Keep every version of your work and put it online.

## Key points
- Git remembers every version of your project. A commit is a save point with a message.
- add picks the files, commit takes the snapshot, push sends it to GitHub.
- `.gitignore` lists what Git skips: videos, passwords, the .venv folder.
- A README is the front page of your repo. You can write one with a program.

## Task 1: Write a README
Ask for the project name. Then write a file called `README.md` with three lines: `# ` and the name, an empty line, then `Made with Python.` For the name `Call Sheet Maker` the file holds:

`# Call Sheet Maker`
``
`Made with Python.`

Hints, in order:
1. Change what goes inside f.write(...). It must be an f-string so the name can go in.
2. Use \n for a new line. Two \n in a row make the empty line.
3. f.write(f"# {name}\n\nMade with Python.\n")

Answer:
```python
name = input("Project name? ")
with open("README.md", "w") as f:
    f.write(f"# {name}\n\nMade with Python.\n")
```

## Task 2: Like .gitignore
`.gitignore` is a file of names Git must skip. `all_files.txt` lists the files in a project. Print every file that is NOT ignored, one per line, in the original order.

Hints, in order:
1. Loop over names. For each one, check whether it is in the ignored list.
2. `if name not in ignored:` is the check. Print the name inside it.
3. for name in names:
    if name not in ignored:
        print(name)

Answer:
```python
with open(".gitignore") as f:
    ignored = f.read().split()
with open("all_files.txt") as f:
    names = f.read().split()
for name in names:
    if name not in ignored:
        print(name)
```

## Task 3: Star rules
Real `.gitignore` files also have rules like `*.mp4`, which means every file ending in `.mp4`. A file is ignored if its name is listed, OR if `*` plus its suffix is listed (`Path(name).suffix` gives `.mp4`). Print each kept file as `Tracked: name`, then how many were ignored. Example:

`Tracked: main.py`
`Tracked: README.md`
`Tracked: notes.txt`
`Ignored: 3`

Hints, in order:
1. Make star = "*" + Path(name).suffix inside the loop. For clip1.mp4 that gives *.mp4.
2. If name in ignored or star in ignored: add 1 to skipped. Otherwise print the Tracked line.
3. Only the else branch prints. The if branch just does skipped += 1.

Answer:
```python
from pathlib import Path

with open(".gitignore") as f:
    ignored = f.read().split()
with open("all_files.txt") as f:
    names = f.read().split()

skipped = 0
for name in names:
    star = "*" + Path(name).suffix
    if name in ignored or star in ignored:
        skipped += 1
    else:
        print("Tracked:", name)
print("Ignored:", skipped)
```

## Editor tip (VS Code and Cursor): Git with buttons
The Git commands from today also live in a panel: **Ctrl+Shift+G** opens Source Control. Changed files are listed. Click one to see old and new side by side (a **diff**). Type a message and click Commit to make the save point. Same thing as the commands, just clicks.

## On the PC: First commit and push
Your work is only safe and shareable once it is in Git and on GitHub. You make a tiny repo today so the steps are familiar before the capstone.

1. Open VS Code, then Terminal, New Terminal. Type `git --version` and press Enter. You should see `git version 2` and numbers. If it says not recognised, close VS Code completely and open it again, then retry.
2. Tell Git who you are, once only. Type `git config --global user.name "Your Name"` and press Enter. Then `git config --global user.email "you@example.com"` using the email on your GitHub account. Nothing is printed when it works.
3. Make a project folder: click File, Open Folder, open Python 30 Work, click New Folder in the window, name it `hello-git`, then click Select Folder. Click Yes if it asks you to trust it.
4. Open a new terminal (Terminal, New Terminal). The last line should end with `hello-git>`. If not, close the terminal with the bin icon and open another.
5. Make three files with the New File icon in the left panel. Name them `README.md` (type `# Hello Git` inside), `hello.py` (type `print("Hello from Git")`) and `.gitignore` (type `.venv/` on line one and `secrets.txt` on line two). Press Ctrl+S in each.
6. Type `git init` and press Enter. It says `Initialized empty Git repository`. Then type `git branch -M main` and press Enter (nothing is printed).
7. Type `git status` and press Enter. Your three files show in red under Untracked. Red means Git sees them but is not saving them yet.
8. Type `git add .` and press Enter (the dot means everything). A line-endings warning may appear: ignore it. Type `git status` again: the files are now green.
9. Type `git commit -m "First commit"` and press Enter. It says `3 files changed`. If it says Please tell me who you are, redo step 2.
10. Open github.com in your browser and sign in. Click the plus at the top right, then New repository. Name it `hello-git`, pick Public, do NOT tick any boxes to add a README or .gitignore, then click Create repository.
11. GitHub shows a page with commands. Find the box that says push an existing repository from the command line. Copy its two lines (`git remote add origin ...` and `git push -u origin main`) and paste them into the VS Code terminal, one at a time, pressing Enter after each.
12. A window may pop up asking you to sign in to GitHub. Click Sign in with your browser and approve. The push ends with `branch 'main' set up to track 'origin/main'`.
13. Refresh the GitHub page. Your three files are there and the README is shown as the front page.
14. Make a second save point: change the text in hello.py, press Ctrl+S, then type `git add .`, `git commit -m "Change greeting"`, `git push`. Refresh GitHub and click the Commits link to see both save points.
