# Day 18: Catch the crash

Tutor notes for a helper model. Explain simply, give a hint before the answer, no em dashes.

**Idea of the day:** Stop bad input from crashing your program, and ask again until it is right.

## Key points
- `try:` runs risky lines. `except ErrorName:` runs if that error happens.
- Name the error you expect. ValueError for bad conversions, ZeroDivisionError for dividing by 0.
- `while True` plus `try` plus `break` asks again until the answer is valid.
- You can stack several `except` blocks under one `try`.

## Task 1: Fill in the error name
The program asks for km. If it is a number it shows `Got 10`. If not it must show `Not a number`. The blank `___` is where the error name goes. Replace it.

Hints, in order:
1. The blank is the name of the error that int("ten") causes.
2. That error starts with Value.
3. Replace ___ with ValueError.

Answer:
```python
text = input("Km? ")
try:
    km = int(text)
    print("Got", km)
except ValueError:
    print("Not a number")
```

## Task 2: Ask again until valid
Ask `Hours? ` until a whole number is typed. For each bad answer show `Try again`. Then show the pay at R150 an hour, like `Pay: R1200` for 8 hours.

Hints, in order:
1. Inside the loop you need a try, then an except ValueError.
2. In the try: hours = int(text) and then break. In the except: print("Try again").
3. try: on its own line, then indented hours = int(text) and break. Then except ValueError: and print("Try again"), lined up with try.

Answer:
```python
while True:
    text = input("Hours? ")
    try:
        hours = int(text)
        break
    except ValueError:
        print("Try again")

print(f"Pay: R{hours * 150}")
```

## Task 3: Safe pace
The pace program crashes on bad input. Wrap it in one `try`. Show `Numbers only` for a ValueError and `Km cannot be 0` for a ZeroDivisionError. Good input still shows the pace, like `6.00 min per km`.

Hints, in order:
1. Put the three lines inside a try, indented by 4 spaces. Then add two except blocks.
2. except ValueError: prints Numbers only. except ZeroDivisionError: prints Km cannot be 0.
3. The two except lines are lined up with the word try, not indented.

Answer:
```python
try:
    minutes = int(input("Minutes? "))
    km = int(input("Km? "))
    print(f"{minutes / km:.2f} min per km")
except ValueError:
    print("Numbers only")
except ZeroDivisionError:
    print("Km cannot be 0")
```

## Editor tip (VS Code): Step through line by line
While paused at a breakpoint, **F10** runs exactly one line and pauses again. Watch the variables change as you go: it is your program in slow motion. **F5** carries on to the end, **Shift+F5** stops. This finds bugs faster than staring.

Try at the PC: Put a breakpoint on the first line of a loop. Press F5, then press F10 several times and watch the counter change in Variables. Shift+F5 to stop.
